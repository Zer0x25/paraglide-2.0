# Post-mortem: fallo en build Docker de API por ECONNRESET en @prisma/engines postinstall

1. **Causa raíz**: Durante `npm ci` en el Dockerfile de la API (`apps/api/Dockerfile`), `@prisma/engines` ejecutaba su script postinstall (`node scripts/postinstall.js`), el cual intenta descargar binarios del query/schema engine desde `https://binaries.prisma.sh`. En Docker BuildKit, las etapas `prod-deps` y `build` corrían concurrentemente, compitiendo por conexiones al CDN de Prisma; al ocurrir un `ECONNRESET`, Node.js 22 arrojó una excepción no capturada en `triggerUncaughtException` que abortó el build. Además, dicha descarga en `npm ci` era redundante y ciega porque el schema Prisma no estaba copiado aún y `npx prisma generate` se ejecutaba explícitamente en el paso siguiente con los binaryTargets correctos.
2. **Señal que lo habría revelado antes**: El log de CI indicaba claramente `#16 npm error path /app/node_modules/@prisma/engines` y `npm error command sh -c node scripts/postinstall.js` con `ECONNRESET` durante `npm ci`.
3. **Regla nueva**: En Dockerfiles que ejecuten `npm ci` para proyectos con Prisma, usar `--ignore-scripts` y `ENV PRISMA_SKIP_POSTINSTALL_GENERATE=true` para deshabilitar descargas desordenadas de red en el paso de instalación. La descarga y generación debe confinarse a `npx prisma generate` con reintentos controlados (`for i in 1 2 3; do npx prisma generate ... && break || sleep 3; done`).
